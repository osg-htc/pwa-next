Help

How this service works, and how to do the common jobs. For what each kind of test measures, see Test types.

What this service does

It holds the measurement plan for a set of perfSONAR hosts: which hosts test to which, with what tests, how often, and where the results go. Every change is published straight away as pSConfig templates, which the perfSONAR hosts read and turn into scheduled tests.

A perfSONAR host subscribes once, to its own address, and from then on picks up every mesh it belongs to:

psconfig remote add {{ public_url }}/auto/$(hostname -f)

Hosts check for changes about once an hour, so a change here reaches them within the hour.

The building blocks

HostsperfSONAR hosts. Most come from the perfSONAR Lookup Service by themselves; add one by hand only if it does not register there.
Host groupsSets of hosts that test together. A group can list hosts by name, include other groups (and follow their changes), and pick hosts by rule, for example every host in a Lookup Service community.
TestsWhat to measure and how often: a test type (throughput, latency, traceroute…), its options, and a repeat interval. One test can be used by many meshes; changing it changes all of them.
ArchivesWhere results are sent, usually an HTTP archive pointing at a central OpenSearch/Logstash.
MeshesA published configuration, made of tasks. Each task runs one test either between every pair of hosts in one group, or between each host of one group and each host of another. A mesh also says which archives receive its results.

Common jobs

Add a site's perfSONAR host to existing meshes

  1. Make sure the host is known: search for it under Hosts (choose “All known hosts”). If it is not there, check that it registers with the Lookup Service, or add it by hand.
  2. Open each host group it should be in, type part of its name under “Add hosts”, and click Add. Every mesh that uses the group includes the host from then on.
  3. On the host, subscribe once with the psconfig remote add command above.

Remove a host from everything

Open the host under Hosts and choose “Remove this host from everything”. You see every group and mesh it is in before confirming.

Start a new mesh

  1. Create the host group(s), or reuse existing ones.
  2. Pick existing tests, or create new ones under Tests.
  3. Create the mesh under Meshes, choose its archives, and add a task for each test. Each task shows how many hosts and test pairs it creates.
  4. Use “Preview the JSON” to see exactly what perfSONAR hosts will receive.

Change how often a test runs, or its options

Edit the test. Its page lists every mesh and task that uses it; all of them change. To change only one mesh, make a copy of the test and point that mesh's task at the copy.

Give someone access

People appear under People after they have signed in once. Give access on an item's own page (“Who can change this”), or for every item of a kind under People. Teams let you give a whole group of people access in one step.

Who can change what

Anyone signed incan look at everything.
Contributor (host groups)can add and remove hosts.
Editorcan change the item.
Ownercan change and delete it, and decide who else has access. Whoever creates something owns it.
Creator (for a whole kind)can create new items of that kind.
Service administratorcan do everything, including managing people and branding.

Every change is recorded with who made it, under History.

When something looks wrong

  • The Overview lists what needs attention: tasks withheld because pScheduler would reject their test, hosts that have stopped registering, archives that perfSONAR 5.3 will reject.
  • Nothing invalid is ever published: a task whose test has a problem is left out until the test is fixed, and the rest of the mesh keeps working.
  • Reports show the load each host carries, measurements made twice by different meshes, hosts that may not support their tests, and what is tested between any two hosts.
